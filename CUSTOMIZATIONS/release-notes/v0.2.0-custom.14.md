# v0.2.0-custom.14

基于上游 formulahendry/vscode-acp 0.2.0（commit e7371659）

## 本版本自定义改动（2026-10-11 · CUSTOM-20261011-233 / 234 / 235）

- **233 / 235　自定义模型（`acpc.customModels`）**：输入框的模型下拉此前完全由 agent 上报，
  客户端无法添加模型。现在可在 settings.json 配置自定义模型，它们会出现在模型下拉里：

  ```jsonc
  "acpc.customModels": [
    { "modelId": "grok-4.6[1m]", "name": "Grok 4.6" },
    { "modelId": "qwen3.8-max[1m]", "name": "qwen3.8-max" }
  ]
  ```

  `modelId` 是发给 agent 的模型标识，`name` 是下拉里的显示名。注入发生在**会话创建/加载/恢复**时
  （经 ACP `_meta.extraModels`），所以改完要**新建会话或重开会话**才生效。

  > ⚠️ **本功能需要一个支持 `_meta.extraModels` 的 fork 桥**（见下节）。运行 stock
  > `@agentclientprotocol/claude-agent-acp` 时该字段会被忽略，模型不会出现。

- **234　错误提示更可读**：agent 报错时优先显示 `RequestError.data.details`，而不是笼统的
  `Internal error`。例如切到模型列表里没有的模型，现在会直接说
  `Invalid value for config option model: xxx`。

## ⚠️ 本版本起，Claude Code agent 改指向 fork 桥

`_meta.extraModels` 是本仓库配套 fork 桥自己加的扩展字段，**上游 stock 桥不识别**。
为让自定义模型生效，本仓库配套 fork 了一份桥：

- 仓库：<https://github.com/zouv/claude-agent-acp>（fork 自 `@agentclientprotocol/claude-agent-acp@0.89.1`，
  commit `63ecd66`），补丁即 `_meta.extraModels` 的解析与注入 + 一个 `prepare` 构建脚本。
- **在 settings.json 里把 Claude Code 指向它**：

  ```jsonc
  "acpc.agents": {
    "Claude Code": {
      "command": "npx",
      "args": ["-y", "github:zouv/claude-agent-acp"],
      "env": {}
    }
    // …其余 agent 按需保留…
  }
  ```

  首次连接会慢一点（npx 需要 clone + `tsc` 构建 fork，之后有缓存）。

> 说明：`acpc.customModels` 里的模型最终能否被网关接受，由网关/账号决定——例如网关不认
> `grok-4.6` 时会返回 `Couldn't confirm model … with the API`，与扩展和注入无关。

## 与上游并存的说明

本扩展的命令前缀为 `acpc.*`（上游为 `acp.*`），扩展 id 为 `zouv.acp-client-custom`，
可与上游 `formulahendry.acp-client` 同时安装、独立配置。

## 安装

下载下方的 `zouv.acp-client-custom-0.2.0-custom.14.vsix`，然后：

```
code --install-extension zouv.acp-client-custom-0.2.0-custom.14.vsix
```
